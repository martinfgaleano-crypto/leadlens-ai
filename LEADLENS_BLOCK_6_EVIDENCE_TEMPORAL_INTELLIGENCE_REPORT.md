### Persistence decision

Migration `042` will add only the missing normalized intelligence core:

1. `intelligence_evidence` — canonical, append-oriented evidence records with
   date provenance, source independence, duplicate/contradiction metadata,
   methodology and supersession.
2. `intelligence_claims` — scoped, time-bounded claims with deterministic
   corroboration state and confidence.
3. `intelligence_claim_evidence` — explicit supporting, contradicting or
   contextual relationships.
4. `intelligence_account_states` — idempotent material historical snapshots and
   computed change payloads.
5. `intelligence_dossiers` — versioned internal-only dossier payloads.
6. `intelligence_client_contexts` — explicit client constraints; absent values
   remain unknown and are never inferred.

There is no separate change table: material changes are deterministic outputs
stored with the new account state, avoiding another lifecycle and source of
drift. Existing Vault and report tables remain authoritative for their current
purposes.

Migration `042` is generated by this block but is not applied automatically.
Until it is applied, the repository layer must fail closed and controlled pilot
artifacts remain auditable local persistence, clearly marked as not yet promoted
to Supabase.

### Implementation invariants

- Canonical URL duplicates and syndicated copies count once.
- Independent corroboration requires different source ownership or materially
  independent origin, compatible entity resolution, compatible time scope and
  semantically compatible claims.
- Publication date has an explicit state:
  `exact`, `inferred`, `retrieved_only`, `conflicting`, `invalid`, or `unknown`.
- Freshness thresholds depend on claim category; no universal recency threshold.
- First observation yields `not_measured`; later comparisons emit only material,
  idempotent changes.
- Timing language remains conservative and cannot claim purchase intent, budget
  or vendor search without direct evidence.
- Client priorities and exclusions are used only when explicitly supplied.
- Internal dossiers are not customer-facing reports and do not alter ranking.
- No provider call may exceed the controlled shortlist, query cap or cost cap.
